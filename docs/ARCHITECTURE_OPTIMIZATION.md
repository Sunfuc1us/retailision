# 架构优化 — 2026-11-11

本次修改按推理、识别迭代、交互顺序实施。保持本地 CUDA 推理，历史模型和数据集不替换。

## 推理

Web 管线只编码每个实例的局部无损 Mask，并返回 `mask_preview_path`、`mask_origin`、`image_size`。下载原有 `mask_path` 时还原完整尺寸 PNG。CLI 默认保留原有全尺寸文件输出。DINO PyTorch 路径按最多 16 个 ROI 分批提取；其他部署适配器继续使用其现有单 ROI 接口。图库精确计算余弦分数后向量化聚合到 SKU，建库时预计算 SKU 分组，保留不同 SKU 的 Top-2 拒识语义。

Workbench 保留本次全部候选，更改目标商品只筛选结果；更改图片、模型、Backend 或检测阈值会清除分析结果。显式“重新分析”会再次请求模型。显示请求耗时与管线计时，前者到收到 API 响应为止，不含画布完成绘制。

RTX 4090，六 SKU / 90 个参考向量，3024×4032，同一张图片六个候选、阈值 0.3：

| 测量 | 修改前两次热请求 | 修改后两次热请求 |
|---|---|---|
| 点击至 API 响应 | 848–928 ms | 469–500 ms |
| 管线内部 | 601–655 ms | 365–379 ms |

首次请求仍约 4 秒，含模型加载。样本量仅支持定点工程对比，不是 P95 基准或零售精度结论。证据位于 `work_dirs/architecture_optimization/{before,benchmark}.json`。六个下载 Mask 与修改前逐像素一致，Box、SKU 及接受/拒绝结果一致，余弦分数最大差 2.384e-7。

## 识别迭代

默认六 SKU 训练 batch 改为 12，训练前检查每类采样约束；验证参考库使用固定推理预处理，训练增强只用于训练 batch。合成 fixture 的单轮 CUDA 投影头训练已完成，仅证明训练流程可运行。

正式迭代仍需独立采集组：冻结主干训练投影头 → 用 `tools/build_gallery.py --projection ...` 构建新图库 → 用独立已知/未知样本重新校准 → 新推理配置绑定模型、projection、图库和策略。当前 15 图同场景 no-split 数据不能支持独立泛化结论，因此没有替换当前商品权重。

预检读取已有图库 manifest，比对 gallery_version、主干路径与 projection 路径；使用投影头时必须有模型来源记录。它不能发现同一路径内权重被替换，所以模型和投影头仍须遵守不可覆盖版本目录的项目约定。

图库增删 API 在写入前将原图库保存到同级 `gallery_history/<id>/`，修改后生成新的 gallery_version，清除当前 runtime 的校准策略。调用方需用返回的新版本重新校准并更新推理配置后重载；旧校准不能继续用于修改后的图库。新增配置预检会拒绝版本不一致。
