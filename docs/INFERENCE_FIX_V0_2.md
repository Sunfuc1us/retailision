# v0.2 推理耗时与误识别定点修复

2026-11-11（Asia/Shanghai）。当前 8018 服务已加载修复，模型仍为 `retail_6sku_v002`。

## 定位与修改

用户反馈图为 `/home/gzh/下载/demoroom/9.jpg`，4284×5712。对真实离线 CUDA 管线进行 cProfile 定位：11 个候选的识别阶段约 7.26 秒，其中 `mask_crop` 约 5.69 秒、PNG 写盘约 1.14 秒，而 DINOv2 特征提取约 87 毫秒。

`mask_crop` 原来对每个候选复制并屏蔽整张原图。现在先求 Mask 边界，只裁剪、转换和屏蔽局部 ROI，保持原有 5% 上下文、灰色背景和像素结果。Mask PNG 使用较低压缩级别，保留原分辨率、8 位灰度和无损像素。没有改动模型输入缩放、神经网络、权重、图库或检测阈值，也没有用缓存结果替代实际推理。

原 v0.2 工程策略 `similarity=0, margin=0` 会接受几乎所有正余弦 Top-1，混合货架上的陌生商品因而被分配到六 SKU。现已启用临时拒识策略：默认 SKU 相似度 ≥ 0.72，第一、第二个不同 SKU 的分数差 ≥ 0.005。针对旧图中药盒与鸭屎香柠檬茶相似度 0.768 的实际误匹配，该 SKU 的最低相似度单独提高到 0.80。

配置位于 `configs/inference/retail_6sku_v002_policy.json`，由现有 v0.2 推理配置引用。旧的零阈值文件保留在模型目录中供历史追溯。策略根据本次反馈图和三张旧照片复核选择，仍标记 `calibrated=false`、`production_eligible=false`，不是独立验证集校准。

界面改为明确显示“商品检测分数”和“SKU 相似度”，框标签注明“检测”，并说明检测分数不代表 SKU 身份、余弦相似度不是正确率。被拒绝的候选显示“未确认 SKU”及相似度不足或候选差值不足等原因。

## 实际耗时

RTX 4090，retailvision-deploy 环境，PyTorch FP32、CUDA，本机原图、检测阈值 0.95、11 个候选。下表优化后为真实 HTTP 请求在模型加载后的三次中位数；完整上传、图像解码和 HTTP 返回中位数为 1525.3 ms。

| 阶段 | 用户反馈 | 修复后中位数 |
|---|---:|---:|
| 总推理时间 | 6979.6 ms | 1457.2 ms |
| 识别阶段（含 ROI、特征、检索、Mask 输出） | 6715.0 ms | 1133.2 ms |

总耗时下降约 79%，识别阶段下降约 83%。同环境独立进程的带 profiler 暖机对比为 7507.3 → 1380.1 ms。11 个候选的 Mask 逐像素一致，Box 和 Top-1 相同，相似度最大差值为 0；速度提升没有依赖减少候选或改变识别特征。

首次请求包含模型加载：本次服务重启后首个 HTTP 请求耗时 4687.2 ms，其中管线计时 1676.3 ms。以上性能数字不应当作冷启动耗时。默认 0.3 阈值会保留更多候选，页面实测 23 个候选总推理约 2865 ms，耗时随实例数量增长。

## 反馈回归

在同一张货架图的 23 个候选中，人工按原图复核为 5 个已知 SKU 候选和 18 个陌生候选。最终真实 API 返回保留 5 个正确身份，拒绝全部 18 个陌生候选；查询雪碧或芬达均只返回对应的一个实例。

三张旧照片继续检查：6 个已知商品与标注匹配的 Mask 均保留正确 SKU，第三张图的 3 个药盒候选均拒绝。旧照片仍存在重复或不完整分割 Mask，本次未重训分割模型。15 张训练图已有 90 个预测分数重放最终拒识策略，90 个仍通过；此项只检查门槛对已有结果的影响。

这些照片已参与调试或门槛选择，不能报告为独立商品准确率或未知 SKU 的总体误接受率。未知商品仍可能与图库高度相似，后续独立采集数据才可支持正式校准结论。
